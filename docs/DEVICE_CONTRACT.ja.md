# OSTF 3.4 — デバイス共通読取・編集契約

対象：OSTF Player、Composer／Chord Arranger、Song Writer、Drum Arranger、Editor、および他の実装。これは**実装に課す仕様**であり、各デバイスが既に対応したという証明ではありません。

## 1. すべてのReader

- root.versionを最初に確認し、その版の正本で読む。3.4では通常の曲情報に拡張を要求しない。未知版をC majorやPopの既定曲に化けさせない。
- song.keyを初期キー、timeline.keyChangesを時刻別キーとして読む。キーとscale、読込時Originalと一時Transposeを区別する。
- ジャンルはsong.genres、作者等はcontributors＋song.credits、ボイシングはchord.voicing、テンポ・拍子はtimelineを読む。曲名・配列位置・デモセレクター名から代用しない。
- 未指定、無調、未対応、読取失敗を別の状態として表示する。読み取れないキーをC majorと表示して正常扱いしない。
- 曲全体のlanguageと歌詞文書のlanguageを混同しない。ユーザーの日本語曲名・歌詞・ジャンル名をUI言語に合わせて上書きしない。
- ノートが演奏の正本。コード、voicing、原型、候補、生成意図は読込時に自動実体化・再適用しない。

## 2. Writerと編集担当

| デバイス | 通常の変更範囲 | 別途承認なしに変更しないもの |
|---|---|---|
| Player | 原則読取と一時試聴 | ファイルのキー・テンポ・音高・クレジット・生成関係 |
| Composer / Chord Arranger | 明示選択した構成・和声・曲情報・伴奏対象 | 既存主旋律、歌詞、他担当の演奏、未解釈Core |
| Song Writer | 明示選択した主旋律・歌詞・担当トラック | Masterの構成、和声、テンポ、拍子、キー、ジャンル |
| Drum Arranger | 明示選択したドラム内容・関連Kit/Slot・生成関係 | 音程ノート、曲全体のキー、主旋律、歌詞、他キット |
| Editor | 利用者が選んだ差分と統合先 | 選択していない全情報・不明な参照内部 |
| 第三者デバイス | 利用者が指定した所有範囲 | 名前やIDが似ているというだけの他対象 |

「担当範囲」はフォーマット内にアプリの独占権を設ける意味ではありません。書出操作の対象を明示し、未変更データを保持する契約です。トラックIDは文書内識別子で、異なる文書の同じIDを同一トラックと断定しません。

## 3. 共通キー解決手順

```
initial = song.key があればその値、なければ未指定
current(t) = at <= t の最後のkeyChanges.key、なければinitial
preview(t) = current(t)にアプリの一時移調を表示上適用
```

keyChangesのatは1以上。tick 0の正本はsong.keyだけです。初期キーがなくても後のキー変更は保持できます。複数scaleが一致した場合は複数文脈として残します。key.label、Camelot表示、五度圏の位置を逆算して正本を上書きしません。

## 4. ファイル保存の最低契約

読み込んだ未対応Coreを保持できない実装は、別名保存であっても黙って消さず、読取専用または保存拒否とします。明示的な変換・ダウングレードでは、損失項目を示して承認を得る必要があります。

ID参照の削除、alignmentの欠落、キット所属の破壊、局所開始と絶対開始の混同、PPQ丸め、同音重複の結合、ゲートの切詰めを「正常保存」に含めません。第三者の未知拡張は精度を含めて保持するか、保持できないことを報告します。

## 5. 再生成・同期・候補選択

生成した結果は具体的なCore notesへ確定します。保存されたseedやGrooveをPlayerが再実行しません。候補選択とclip.enabledは一括更新し、読み込んだだけで選択を強制しません。原型置換は全関連Instanceと保護対象を含めて一括成功・一括失敗にします。

Velocityの独立・連動を混同しません。3.4以前の原型から読み込んだ場合はindependent。linkedを選ぶ場合のみ原型と実ノートの有無・値の一致を要求します。

## 6. 共通情報の競合

| 状態 | 処理 |
|---|---|
| 3.4 Coreと旧Player拡張が一致 | Coreを使用。旧値は互換資料 |
| 両者が不一致 | Coreを使用し、旧値との不一致を表示。勝手に修正しない |
| 3.4 Coreは未指定、旧拡張に値だけある | 未移行の旧データと表示。通常読取で勝手に昇格しない |
| 3.3原版を読み込む | 元版として保持。明示的な3.4移行を別操作にする |
| 編集後に標準編集関係を再計算できない | statusをstale/unverified。確定ノートは保持 |
| Core自身の参照が不正 | 正常文書として保存しない。staleでは救済しない |

## 7. デバイス側の対応完了条件

仕様配布とは別に、実装者は読取元・保存先の変更、既存Coreの保持、旧版の版別読取、明示移行、未対応の表示、対象別編集の適用を行います。ソフトウェアの実行・UI・音声の確認はデバイスのリリース工程です。本パッケージではその動作確認を行っていません。
