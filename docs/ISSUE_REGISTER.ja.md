# OSTF 3.4 — 問題台帳と対処範囲

**証拠の区分：**「確認」は今回取得した3.3仕様・Schema・添付デモに存在する構造を確認したもの。「設計レビュー」は将来の不一致を避けるため追加した規則で、既存アプリで症状を再現したという意味ではありません。Player・Composer等の実行は行っていません。

元の11デモは3.3 Schemaの構造検査に適合しています。**独自拡張に情報があること自体が、直ちに3.3形式違反だったわけではありません。** 問題は、全デバイスで共通解釈すべき情報の標準保存先が不足・未利用だったことです。

## 規格追加ではないもの

ジャンル・ボイシング・クレジット・テンポ・拍子・構成role・主旋律・演奏Velocity・ドラムIDは既存Coreを使います。既存項目を再定義して二つの正本を作りません。全体スケールの空欄だけを理由に曲を不正としません。resourcesが空でも履歴があることは不正ではありません。

## 今回の範囲外を拡張必須へ置き換えない

CC、Pitch Bend、Aftertouch、MPE、音声トラック、音源やDAWの完全復元、連続テンポ曲線、完全な楽譜表現は本版の適合範囲外です。未完成の項目を「後から誰かの拡張で解決することが必須」という設計にはしません。これらを将来共有要件として採用する場合は、型・時間・発音・保持規則を持つ次版を策定します。

アプリ固有生成アルゴリズム・DSP・プリセットまで共通Coreに詰めることも行いません。現在の曲の理解には不要とし、標準化した生成意図と確定演奏だけを交換します。

## 解決の意味と限界

上表は保存先・型・優先順位・移行規則の仕様上の対処です。すべての既存デバイスを直したこと、すべての将来要望を予見したこと、生成音楽の品質や音声互換性を保証することではありません。実装側の対応対象は[共通デバイス契約](DEVICE_CONTRACT.ja.md)に分離しています。
